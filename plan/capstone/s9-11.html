工程与说法

阶段 9：git + 别把口令交出去 —— 1 晚，但越早越好

只要会六个命令：init status add commit log diff。
作用一句话说：它就是游戏存档。改坏了 git checkout -- 文件名 读档回来。

内容为什么
上面那六个命令 · 【必会】
提交前必看 git status【必会】真的两次差点把数据库口令、签名密钥提交进仓库——它们本来就该被 .gitignore 挡住，但那一次规则还没加。以后每次提交前扫一眼这个列表，多出来的文件就是事故现场
.gitignore 是干什么的 · 【必会】一句话：本地要有，仓库里不能有的东西（口令、临时产物、装的依赖）
git diff 看一眼别人改了什么 · 【必会】这是"AI 写的"和"你交上去的"之间唯一的界线。看不懂的那段就别存档，回去问
换行符 CRLF / LF · 【看得懂】只需要记一条：.bat 文件一旦被换成 LF，双击就跑不起来了。仓库里已经用 .gitattributes 钉死，别去动它
分支、rebase、远程仓库、pull request · 【别学】单人项目，main 一条线走到底

过关检验：随便改坏一个文件，用 git checkout -- 那个文件 读档回来；再 git status 确认干净。

阶段 10：测试与"改完对不对" —— 3 晚

原清单完全没提测试，可项目里已经有 28 条在跑，答辩很可能被问"你怎么验证的"。
不需要会写框架，只需要会跑、会读、敢加一条。

  • 跑一遍：backend/.venv/Scripts/python.exe -m pytest tests -q 【必会】
  • 看得懂失败输出：哪个用例、期望什么、实际什么 【必会】
  • 一条测试在测什么：造数据 → 调接口 → 对答案 【必会】 照着 tests/test_compare.py 抄一条新的
  • "未公布不能去争最优"这类规则有测试钉住 【必会】 答辩金句：把比较规则写成了会自己报错的测试，所以改代码不会悄悄把结论改错
  • 后台那个"数据体检"页在查什么 【看得懂】 范围外的离谱值、缺得太多的字段——它防的是录错数据，不是代码 bug
  • 覆盖率、mock、CI 【别学】

过关检验：给 /api/compare 加一条测试——只有一台手机公布重量时，那一格不许出现"最优"。跑一次让它红，再确认它绿。

阶段 11：会被问、但其实很好讲的概念

概念一句话答法
前后端分离页面只管显示，数据由另一个程序通过接口给，两边各改各的互不影响 · 【必会】亲手跑通阶段 0—4 就能用自己的话说
RESTful APIURL 说"要什么东西"，请求方法说"干什么" · 【必会】
元数据驱动：字典表决定页面长什么样参数叫什么、要不要显示、往哪边算好，都存在数据库里；加一个参数不改代码 · 【必会】这是整个项目的立身之本，原清单里居然没有这一条
未公布 vs 不支持，是两件事NULL 是"官网没写"，0 是"确实没有"；前者不参与比大小，界面上单独显示"未公布" · 【必会】答"空值怎么处理"就答这句
登录鉴权（发一张票）登录成功发你一张带签名的票，之后每次请求带着它；票 8 小时过期 · 【看得懂】
为什么口令存成一串乱码存哈希不存明文；库被拖走也拿不到口令。项目用 bcrypt，一条口令还要加"故意算一遍错的"防猜用户名 · 【看得懂】
部署：单端口前端 build 出静态文件，后端直接托管它，整站就一个 http://localhost:8000；刷新深层页面要靠"找不到文件就回首页"兜住 · 【必会】因为答辩用的就是这个地址
一份状态只有一个正本对比页看哪几台由地址栏决定，排行榜看哪项也由地址栏决定——两处都能改就一定不同步 · 【必会】
缓存后端读进内存会缓存，浏览器也会缓存；改了没变，先想这两处 · 【必会】
备份与异地本地一份、git 存档一份；备份脚本必须排除口令密钥，否则等于把钥匙也拷过去了 · 【看得懂】
Docker、消息队列、Redis、微服务、爬虫、推荐算法—— · 【别学】开题没承诺的别自己加戏，加了答辩就要解释
